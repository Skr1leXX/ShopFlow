# E2E-тесты (Playwright)

Сценарии с данными работают на **настоящей базе libSQL**: достаточно локального файла SQLite, облачная Turso и аккаунты не нужны.

## Запуск

```bash
echo "TURSO_DATABASE_URL=file:local.db" > .env.local   # или скопируйте .env.example
npm run build                                           # тесты идут против production-сборки
npm run e2e                                             # или npm run e2e:desktop
npm run e2e:report                                      # HTML-отчёт
```

`playwright.config.ts` читает `.env.local`, поднимает `next start -p 3300` и использует установленный Edge/Chrome (или `E2E_BROWSER_PATH`, или `npx playwright install chromium`). Без `TURSO_DATABASE_URL` сценарии с данными пропускаются, остаются проверки заглушки `/setup` (`smoke.spec.ts`).

Перед запуском `global-setup` применяет миграции и создаёт изолированные данные с префиксом E2E: 2 пользователя (админ и покупатель), категорию, 15 товаров, промокод. После запуска `global-teardown` всё удаляет, каталог проекта не затрагивается. Тесты используйте на тестовой базе, а не на базе с реальными данными: они создают и удаляют записи.

## Загрузка фото

Сценарии загрузки фото выполняются только при `BLOB_READ_WRITE_TOKEN` (Vercel Blob). Без токена проверяется, что загрузка честно отвечает «не настроена» и ничего не сохраняет.

## Файлы

| Файл | Что проверяет |
|---|---|
| `auth.spec.ts` | регистрация, вход/выход, смена пароля, подделка cookie, доступ покупателя к `/admin`, защита приватных страниц |
| `catalog.spec.ts` | каталог, поиск, фильтры, сортировка, пагинация, карточка товара |
| `cart.spec.ts` | гостевая корзина, слияние при входе, остатки |
| `checkout.spec.ts` | оформление, цены, промокод, идемпотентность, подмена цены в браузере |
| `admin.spec.ts` | панель администратора: товары, категории, заказы, склад, клиенты, промокоды, экспорт |
| `responsive.spec.ts` | адаптивность (desktop / tablet / mobile) |
| `perf.spec.ts` | число запросов, вес страниц, изображения, заголовки, отсутствие секретов в клиентском коде |
| `smoke.spec.ts` | поведение без базы, 404, заголовки безопасности, экспорт без входа |
