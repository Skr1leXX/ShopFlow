# ShopFlow

Интернет-магазин одежды и аксессуаров с личным кабинетом покупателя и панелью администратора. Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS 4 + **Turso (libSQL/SQLite)** + Vercel Blob.

Проект учебно-демонстрационный: витрина, корзина, заказы, склад и админка работают на реальной базе данных, но **оплата, доставка и письма покупателям не подключены** (см. [Что реально, а что демо](#что-реально-а-что-демо)).

> **Ветки.** `main` — версия на Supabase (PostgreSQL, Auth, RLS). `turso` — эта версия на Turso: вход, сессии, права и транзакции реализованы в коде приложения, потому что в SQLite нет RLS, встроенной авторизации и хранилища файлов.

## Возможности

**Покупатель**
- Главная: баннер, категории, рекомендации, новинки, спецпредложения.
- Каталог: поиск по названию, описанию и бренду; фильтры по категории, цене, размеру, цвету, бренду; сортировка; пагинация. Фильтры хранятся в URL.
- Карточка товара: галерея, цвет и размер, наличие и остаток, избранное, похожие товары.
- Корзина: гостевая (в браузере) и серверная (в БД), слияние при входе, контроль остатков, промокод.
- Оформление заказа: контакты, адрес, доставка и оплата, итог; защита от двойной отправки.
- Личный кабинет: профиль, смена пароля, история заказов, избранное, адреса.
- Регистрация, вход, выход, защита приватных страниц.

**Администратор** (`/admin`, только роль `admin`)
- Dashboard: выручка, заказы, средний чек, клиенты, товары, низкие остатки, график за 30 дней, популярные товары, последние заказы.
- Товары: поиск, фильтры, CRUD, фото, цены и скидки, варианты (размер × цвет), остатки, скрытие.
- Категории, заказы (смена статуса, безопасная отмена с возвратом остатков), клиенты и роли, склад (приход, списание, журнал), промокоды, экспорт CSV.

## Архитектура

```
Браузер ──► Next.js (Vercel)
 UI, корзина  ├─ Server Components ── чтение ──►  src/lib/data/*  ─┐
 гостя        ├─ Server Actions ── изменения ──►  src/lib/actions/* │──► Turso (libSQL)
              │     проверка сессии и роли (src/lib/auth.ts)        │
              │     ядро бизнес-логики: src/lib/core/* ─────────────┘
              └─ proxy.ts: быстрый редирект гостей с /account /checkout /admin
```

- **Доверие только серверу.** Цены, скидка, доставка и остатки считаются в `src/lib/core/orders.ts` из данных БД; браузер присылает только выбор покупателя.
- **Атомарность.** Заказ (`placeOrder`) выполняется одной транзакцией записи: проверка остатков, создание заказа и позиций, списание, журнал склада, промокод, очистка корзины. Транзакция записи SQLite эксклюзивна, поэтому два покупателя не купят один последний товар. Ключ идемпотентности (уникальный индекс `(user_id, idempotency_key)`) защищает от повторной отправки.
- **Права без RLS.** SQLite не умеет политики строк, поэтому доступ контролирует приложение: каждая выборка пользовательских данных ограничена `user_id` из сессии, а каждое админ-действие и каждая админ-страница начинаются с `requireAdmin()` — роль читается из БД, а не из cookie или формы. Ошибка в этих проверках открыла бы данные, поэтому они покрыты тестами.
- **Сессии.** В cookie лежит случайный токен, в БД — только его sha256. Выход, смена пароля и истечение срока (30 дней) закрывают сессию. `proxy.ts` лишь редиректит гостей, подлинность проверяется на сервере.
- **Склад.** Остаток меняет единственная функция `changeStock`: условие `quantity + delta >= 0`, `check (quantity >= 0)` в таблице и запись в журнал в той же транзакции.
- **Без базы приложение не падает**: показывает инструкцию (`/setup`).

## Быстрый старт

Нужны Node.js ≥ 20.9 и npm. Аккаунт Turso для локальной работы **не нужен**: подойдёт файл SQLite.

```bash
git clone https://github.com/Skr1leXX/ShopFlow.git && cd ShopFlow
git checkout turso
npm ci
cp .env.example .env.local      # по умолчанию TURSO_DATABASE_URL=file:local.db
npm run db:setup                # миграции + каталог (34 товара, 6 категорий, 336 вариантов, 3 промокода)
npm run seed:demo               # демо-аккаунты и заказы (необязательно)
npm run dev                     # http://localhost:3000
```

## Настройка Turso

1. Установите CLI ([docs.turso.tech](https://docs.turso.tech/cli/installation)) и войдите: `turso auth login`.
2. База и доступ:
   ```bash
   turso db create shopflow
   turso db show shopflow --url          # libsql://shopflow-<аккаунт>.turso.io
   turso db tokens create shopflow       # токен
   ```
3. В `.env.local` (локально) или в настройках Vercel задайте `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`.
4. `npm run db:setup` применит миграции и загрузит каталог (повторный запуск безопасен).
5. Первый администратор: зарегистрируйтесь на сайте, затем `npm run make-admin -- ваш@email`. Через интерфейс регистрации роль `admin` получить нельзя.
   Либо `npm run seed:demo` создаст `admin@shopflow.demo`, трёх покупателей, адреса, избранное и 8 заказов (задайте `DEMO_PASSWORD` в `.env.local`).

## Загрузка фото (Vercel Blob)

Фото, которые админ загружает в карточке товара и категории, хранятся в Vercel Blob (JPG/PNG/WebP/AVIF, до 5 МБ). Нужен токен: Vercel → Storage → Blob → Create → `BLOB_READ_WRITE_TOKEN` в `.env.local` / переменных проекта. **Без токена** загрузка выдаёт понятное сообщение «не настроена», а фото каталога остаются внешними ссылками Unsplash (они разрешены в `next.config.ts`).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `TURSO_DATABASE_URL` | адрес базы: `libsql://…` или `file:local.db` (на Vercel файл не работает) |
| `TURSO_AUTH_TOKEN` | токен базы, секрет, только сервер |
| `BLOB_READ_WRITE_TOKEN` | токен Vercel Blob, секрет, только сервер (необязателен) |
| `DEMO_PASSWORD` | пароль демо-аккаунтов для `seed:demo` (только локально) |

Ни одна из переменных не имеет префикса `NEXT_PUBLIC_` — в браузер ничего не передаётся. `npm run check:env` проверяет значения; тот же контроль идёт перед каждой сборкой (`prebuild`) и останавливает её, если секрет оказался в публичной переменной или на Vercel указан локальный файл.

## Миграции

SQL-файлы `db/migrations/NNNN_*.sql` применяются по порядку скриптом `scripts/migrate.mjs` (журнал в таблице `_migrations`).

| Файл | Содержимое |
|---|---|
| `0001_init.sql` | 14 таблиц: `profiles`, `sessions`, `categories`, `products`, `product_images`, `product_variants`, `inventory`, `inventory_movements`, `addresses`, `cart_items`, `favorites`, `promo_codes`, `orders`, `order_items`; `check`-ограничения, индексы, уникальный индекс идемпотентности |

Особенности SQLite: деньги — `real`, время — ISO-строка UTC, логические — 0/1; поиск по каталогу идёт по колонке `search` в нижнем регистре, потому что SQLite не понижает регистр кириллицы.

## Тестирование

```bash
npm run verify        # typecheck + lint + unit + тесты БД + поиск секретов + build + анализ сборки
npm run test:db       # бизнес-логика на настоящей libSQL: db/core.test.mjs
npm run test:unit     # CSV, проверка окружения, поиск секретов
npm run e2e           # Playwright: поднимает next start на файловой базе из .env.local (e2e/README.md)
```

`test:db` проверяет: миграции и seed (повторный запуск), расчёт заказа, идемпотентность, гонку за последний товар, откат при нехватке остатка, корзину, промокоды (лимит, срок, минимум), отмену с возвратом остатка и промокода, конечные статусы, склад и запрет минуса, роли, scrypt-пароли, сессии (хэш токена, подделка, истечение).

E2E-набор покрывает регистрацию и вход, смену пароля, подделку cookie, защиту `/admin`, каталог, корзину, оформление заказа, админку, адаптивность и производительность.

## Развёртывание на Vercel

1. Создайте базу Turso (раздел выше) и выполните `npm run db:setup` **с локальной машины**, указав в `.env.local` облачный `TURSO_DATABASE_URL` и токен. Выложите код в GitHub; перед этим `npm run scan:secrets`.
2. Vercel → Add New → Project → импорт репозитория, ветка `turso`. Framework — Next.js.
3. Environment Variables: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, при желании `BLOB_READ_WRITE_TOKEN` (создаётся в Vercel Storage). `DEMO_PASSWORD` не добавляйте.
4. Регион функций выберите рядом с регионом базы Turso.
5. После деплоя: каталог открывается с товарами, регистрация и вход работают, `/admin` под покупателем закрыт.

GitHub Actions (`.github/workflows/ci.yml`) выполняет проверки на файловой базе без секретов.

## Безопасность
- Пароли: scrypt (N=16384) с индивидуальной солью, в открытом виде нигде не хранятся и не логируются. Сообщение и время ответа при неверном email и неверном пароле совпадают.
- Сессии: httpOnly, `SameSite=Lax`, `Secure` в production; в БД только хэш токена.
- Роль читается из БД на сервере при каждом запросе; регистрация всегда создаёт `customer`.
- Секреты только на сервере; сборка проверяется на их утечку (`test:static`), репозиторий — сканером (`scan:secrets`).
- Server Actions Next.js проверяют `Origin`, что защищает от CSRF.
- Заголовки: `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. Content-Security-Policy не настроен.
- Ошибки БД клиенту не показываются: только сообщения бизнес-правил.

## Что реально, а что демо

| | Статус |
|---|---|
| Регистрация, вход, выход, смена пароля | реально (собственная реализация, см. ограничения) |
| Каталог, корзина, заказы, промокоды, склад, админка, CSV | реально |
| Загрузка фото | реально при заданном `BLOB_READ_WRITE_TOKEN`; иначе отключена |
| **Оплата** | **не подключена.** Платёжного провайдера нет, деньги не списываются; заказ создаётся «Новый». В форме есть пометка |
| **Доставка** | **не подключена.** Только расчёт стоимости (курьер 490 ₽, почта 290 ₽, самовывоз и заказы от 15 000 ₽ бесплатно). Служб доставки и трекинга нет |
| Письма | **не отправляются никакие.** Поэтому нет подтверждения email и восстановления пароля по почте |
| Демо-заказы | создаются тем же кодом, что и настоящие, остатки и журнал согласованы; даты сдвинуты назад |
| Фото каталога | внешние ссылки Unsplash |
| Раздел «Настройки» админки | только чтение |

## Ограничения и планы
- **Нет восстановления пароля:** без почтового провайдера отправить ссылку нечем. Забытый пароль меняет только админ базы вручную. План: Resend/SMTP.
- **Нет ограничения частоты попыток входа** — перебор пароля не замедляется. Для публичного показа поставьте перед сайтом Vercel Firewall/WAF или добавьте rate limit.
- **Права держатся на коде приложения, а не на БД** (нет RLS). Любой новый запрос к пользовательским данным обязан фильтровать по `user_id`.
- Не проверено на облачной Turso и Vercel Blob: тесты шли на файловой libSQL; сетевой клиент использует тот же API, но прогон на облаке не выполнялся.
- Нет оплаты, доставки, уведомлений, возвратов, отзывов. Интерфейс на русском, цены в рублях.
- Списки админки без постраничной разбивки (до 500 записей), поиск в них выполняется в приложении.
- Нет Content-Security-Policy.
